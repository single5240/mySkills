# 嵌入式最小实现与交付约束

提炼来源：QW-603 HW1.4 项目 AGENTS.md（2026-10-23 版），2026-10-29 整理。只复用方法；目标项目的源码、工程配置、硬件资料和已确认需求决定具体约束。

## 实现边界

- 沿用当前分层与命名，不因目标架构文档列出目录就创建或迁移模块。应用决定产品策略，驱动负责协议、时序、超时、状态码和恢复；历史例外只在相关任务中处理。
- 外设只有一个责任模块，调用方不重复初始化、调度或关闭。新增文件加入实际参与编译的 Target，不能只放入目录。
- 厂商库原则上不改。确需修改时先说明已确认缺陷或板级适配依据、用户层无法规避的原因、上游差异、影响和回退方式；不顺带格式化。
- 生成器历史标记本身不等于禁止编辑；是否允许重新生成由项目规则决定，不能用生成器覆盖手工配置。

## 检查放在拥有信息的位置

- 对外公开函数检查自身入参；外部输入入口检查通信帧、按键和持久化数据；资源所有者检查地址、长度、寄存器位宽、超时和状态码。
- 模块内 static 函数使用已检查值，不层层重复相同检查。表长、枚举项数等源码常量使用编译期约束；函数指针下标仍在调用前检查并执行既有恢复。
- 每项新增保护应对应系统可能发生的失败，并有明确处理动作。删除检查前确认它不再决定错误码、回滚或显示内容；规则冲突先统一入口。
- 精简不得删除时序、并发、资源边界、超时或掉电保护。若以缩减代码为目标，用原工具链比较资源结果，不假设更短源码一定更省空间。

## 数据、时限与资源

- 核对数组和帧边界、移位范围、计数溢出、换算单位及无符号 tick 回绕；volatile 不替代复合更新和跨上下文一致性分析。
- 固定缓冲说明容量依据、生命周期、所有权、最大并发占用；DMA 缓冲不能在完成前复用。不能仅为避免栈溢出就无审查地增大全局 RAM。
- 大数组、队列、字库或缓冲变更后，用原工具链记录 Code/RO/RW/ZI 增量，评估静态 RAM 和栈余量；替代编译器结果单独标明。
- 有看门狗的裸机系统按项目约定从主循环喂狗。运行期耗时操作拆为有界步骤；底层等待不自行喂狗。确实无法拆分时，先给出最长时限、失败退出和喂狗责任，确认设计例外。
- 存储版本、分区、校验、提交、磨损、旧数据兼容和恢复策略必须有已确认依据。发现源码与目标偏差时分别报告，不把计划写成已实现。修改实现的授权不自动等于允许擦写目标板数据。

## 验证与交付

- 每片修改前选好验证入口，修改后取得匹配风险的新证据，再推进依赖它的下一片。静态检查只能证明其覆盖的约束。
- 从原始需求、数据和控制流复核实现，不能只接受实现者总结或与实现共享假设的测试。
- 区分规范审查与需求审查，区分静态、原工具链编译、主机回归/仿真、上板、仪器和断电注入；缺失依赖写明，不能用替代工具链冒充原工具链通过。
- 修改公开接口行为、引脚/DMA、中断优先级、时钟、存储格式或初始化顺序时，同步唯一权威文档；纯内部修复不扩写无关文档。文档时间格式沿用目标项目约定。
- 检查 git diff --check、Diff 和状态，清理本次生成的缓存，保留用户已有改动；生成物和本地 IDE 配置通常不提交。
- 用户授权提交时，以可独立审查和回退的单一目的分组；同一接口声明、实现、调用方和必要文档保持一起。独立目的分开，不按目录机械拆分。中文标题说明唯一目的，正文说明原因、影响、验证与未验证项、硬件依据及回退方式。
- 交接引用现有需求、设计、Diff 和证据，说明剩余风险及下一步；不将会话状态或一次排查过程扩散为长期规范。提交、推送、烧录和擦写遵循已有明确授权范围。
