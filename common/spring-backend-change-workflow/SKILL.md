# Spring 后端变更与验证工作流

技术方向：`common`；使用范围：`global`。目标是缩小修改范围，并让完成结论与证据相符。

## 先识别任务，再读相关内容

读取工作区状态、目标构建文件和相近实现，确认 Boot/JDK、Wrapper、持久层、测试配置及当前约定。区分依赖管理与实际依赖、构建 profile 与运行 profile；不默认升级版本或更换 ORM、响应格式及目录结构。

| 当前任务 | 最小调查与按需参考 |
| --- | --- |
| 缺陷/异常/集成失败 | 先按下节复现和定位边界，再阅读与根因相关的参考，不先改配置试运气 |
| 事务、缓存或并发变更 | 追踪真实代理调用、提交与异步边界；读[一致性检查](references/consistency-and-mqtt.md#数据库与-redis)及相邻并发小节 |
| MQTT 或设备状态变更 | 核实收发双方和状态关联；读[设备通信检查](references/consistency-and-mqtt.md#mqtt-与设备指令) |
| 测试/构建或完成前检查 | 按需要证明的行为选最小足够测试；读[验证与交付](references/verification-and-delivery.md) |
| 后端变更的提交整理或推送准备 | 按单一目的检查改动与暂存范围；读[Git 交付规则](references/git-delivery.md)，推送需风险告知后的再次确认 |
| 规范整理/文档变更 | 保留项目事实与真实检查入口；只做内容、链接和差异检查，不启动服务 |

纯 CRUD 生成沿用项目技能；部署操作及硬件任务遵循对应授权与规则。本技能无需依赖其他技能安装。只读当前任务需要的小节；研究来源和评估用例仅在维护本技能时读取。

## 缺陷：先证明故障发生在哪里

沿一次真实请求追踪入口 → 授权/业务 → 数据库/缓存 → 异步/消息 → 外部系统，按实际调用裁剪。保留错误原文、复现条件和必要脱敏证据；对照同仓库的正常路径及近期差异。

每轮提出一个可证伪假设，选择能区分原因的最小观测或实验，确认后再修复。不能复现时明确未知项，补充有针对性的日志或隔离实验；不叠加猜测性配置、重试或架构调整。假设被证据否定或修复连续无效时回查边界，不在相同假设上继续堆补丁。

能说明触发条件、根因、影响方/共享状态、修改边界及验证方法后停止扩大检索。源码事实自行核实；必要文件或决定结果的业务/协议语义缺失时说明缺什么并询问，不猜测。用户要求仅分析时保持只读。

## 按风险确定检查深度

文档/无行为小改采用事实核对、最小修改和相关检查；普通功能按可独立验证的行为切片。改变认证授权、数据范围、余额/次数、协议、共享状态或存储/迁移行为时，逐项满足[六阶段通过条件](references/verification-and-delivery.md#高风险变更的六阶段通过条件)。六阶段不要求六份材料或逐阶段审批；已确认的同一操作不重复询问，范围或风险变化时重新确认。推送适用下述专门规则。

## 实现约束

- 保持现有分层、错误语义及 API 契约；公共能力修改检查调用方。不顺带升级框架、引入中间件或重构。
- 校验放在拥有信息的入口或资源所有者，保留权限、数据范围、事务、幂等、超时和恢复保护。服务端检查对象归属及可写字段，不能信任客户端传来的身份或权限。
- 线程池、队列、缓存和重试需有可解释的容量/时限与失败退出；不将无界积压或无限重试当作恢复策略。
- 修改实现与检查真实环境分开。共享服务写入、真实设备指令、数据清理和部署必须符合已授权范围；不要为了验证局部逻辑启动有真实副作用的任务。
- 所有服务器操作以不影响服务器及现有服务正常运行为前提；只读检查也需评估负载。存在运行、性能、数据或安全风险时，先说明具体后果与恢复措施，取得明确确认后执行；风险不明先调查，仍无法判断则暂停。具体边界见[服务器操作与风险确认](references/verification-and-delivery.md#服务器操作与风险确认)。
- 未明确要求不创建 Commit、不推送或部署。即使用户要求推送，也先说明目标、全部待推送提交及自动化触发风险，再次取得明确确认；本地提交授权不包含推送，推送授权不包含部署。按[Git 交付规则](references/git-delivery.md)处理提交粒度和暂存范围。

## 完成判据

报告结论前，检查最终修改对应的实际命令、退出码、执行范围和结果；修改之后的旧结果、零测试或示例测试不能充当业务通过证据。已通过且修改未影响的检查不机械重跑。没有条件执行时明确未验证及限制。

简述修改与原因、验证范围、剩余风险和必要恢复方式；高风险任务对应原始验收项逐项核实。只把已证明的层级写成通过，不将客户端发布成功写成设备执行完成。保留已有修改，Git 操作遵循上述授权与再次确认要求。

项目路径、版本、Topic、业务参数及实测命令仍留在目标项目文档。维护本技能时参阅[来源与取舍](references/source-notes.md)及[行为评估用例](evals/evals.json)；这些材料不作为每次开发的额外流程。
