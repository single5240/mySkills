# 验证边界与交付证据

## 各层证据回答的问题

| 验证层 | 能说明什么 | 不能直接推导什么 |
| --- | --- | --- |
| 主机回归 | 当前输入、事件顺序和故障模型下的逻辑结果 | MCU 指令、寄存器、电气和真实实时性 |
| 原目标工具链构建 | 指定编译配置下可编译链接、资源和链接地址 | 设备运行行为正确 |
| 目标仿真／硬件模型 | 所用模型覆盖的 CPU／外设行为 | 未建模硬件和真实板行为 |
| 实板测试 | 指定板卡、条件、固件下的观察结果 | 未测试条件下的全部行为 |

主机回归与仿真并非同义词。先说明是在电脑原生执行 C，还是执行目标指令，以及模型包含了哪些内核／外设。

## 目标差异

- 核对 `int`、`long`、指针宽度、`char` 符号性、整数提升、位域、结构体填充和对齐，保留实际目标类型约束。协议／持久化明确序列化，不依赖裸结构体布局。
- 不用主机编译器代替 ARMCC、XC8 等原工具链检查；主机通过的扩展语法、库函数或宽整数计算，在目标上可能不成立。
- 主机可辅助检查内存越界、未定义行为，但结果受编译器与检测器支持限制；检测器缺失不应阻止已有相关回归，不宣称没报错就不存在缺陷。
- 通过宏绕过 SFR、汇编或中断修饰后，明确被绕过部分不在验证范围。模拟只检查抽象业务行为，不能证明寄存器地址与清标志语义正确。

## 并发与硬件

- 顺序调用、人工插入中断和电脑线程，只覆盖设计出的交错；`volatile` 不等于原子性或同步。目标上仍需检查临界区长度、读改写、ISR 优先级和内存可见性。
- DMA 模型中的“完成”不代表总线发送结束；核对真实缓冲区所有权、生命周期、对齐及 Cache 清理／失效。测试不应提前释放或自动复制缓冲区来掩盖悬空访问。
- RTOS 应用的状态测试不自动包含真实调度器。若使用主机 RTOS 移植或模拟调度器，声明任务／中断模型及不支持的特性。
- 看门狗、时钟误差、SPI 建立保持时间、GPIO 串扰、射频送达、睡眠唤醒源和真实掉电需目标证据。不要把模型主动触发的唤醒写成无线包能直接唤醒 MCU。

## 最小交付记录

按项目规模保存以下信息，不强制引入新的报告框架：

1. 待测版本、实际路径、源码与必要宏／配置的哈希；记录是否带本地改动。
2. 主机编译器版本、完整编译／运行命令与退出状态，不能只保存 PASS 文本。
3. 测试覆盖的需求、故障模型、随机种子或事件轨迹，以及明确未覆盖的上下文。
4. 新生成日志与临时产物的位置；禁止以历史测试输出代替本次结果。
5. 原工具链构建和资源检查结果，与实板执行／未执行项目分别列出。

示例表述：“当前状态机源码在主机模型下通过回绕、重复输入和取消测试；模拟链路允许指定丢包，无真实射频；原 ARMCC 构建通过；目标时序和实板通信未验证。”

项目路径、编译器安装位置、私有协议与具体验收参数应放在项目 AGENTS.md／测试文档，本技能不维护各项目的历史通过次数。
