# 嵌入式主机回归

技术方向为 `common`，适用于裸机及 RTOS 应用的可分离逻辑。主机回归使用电脑编译器运行当前生产源码，替换必要的硬件接口；测试工具与依赖留在电脑侧，不引入量产固件。

## 判断范围

- 先查项目 AGENTS.md、现有测试入口、生产构建与配套仓库，优先运行相关已有回归。
- 当修改按键、状态机、协议解析、数值边界或存储恢复，或缺陷可在电脑上复现时，选择相关模块测试；双端协议修改增加联合回归。
- 仅文档、格式或低影响且无逻辑变化的修改，不因此新增测试或重跑固件构建。直接涉及电气时序、DMA、ISR 或低功耗时，把目标构建和实板验证列为主要证据。
- 不为测试擅自迁移编译器、加入 RTOS、引入框架或重构整个固件。工具缺失时先查现有安装与可用替代，依赖安装仍遵守用户授权。

## 接入当前生产源码

1. 确认芯片、目标编译器、宏、位宽、编码及模块所有权；记录实际检出路径、版本与本地改动，不能用别处旧副本代替当前源码。
2. 优先将现有模块直接加入主机构建，以链接替身提供时间、GPIO、通信和存储接口。旧工程可逐字提取完整函数作为过渡，但需保存来源与哈希，提取失败就停止，不能静默使用缓存；报告未纳入的调用关系与上下文。
3. 不手抄业务算法、不在测试中维护第二份修正版。确需新增生产接口时保持局部化，不暴露大批内部状态只为让测试更方便。
4. 使用虚拟时间与受控事件推进，故障按明确模型注入；模型仅替换必要边界，不能替业务代码自动补齐漏包、完成保存或推断 ACK。

## 设计与实现

根据任务按需读取：

- [测试设计](./references/test-design.md)：状态转移、虚拟时间、故障注入、双端联合、存储模型和可信度检查。
- [验证边界](./references/validation-boundaries.md)：主机与目标差异、ISR／DMA／RTOS 的覆盖限制、结果交付格式。
- [报告编写与归档](./references/test-reporting.md)：交付或用户要求报告时读取，说明标准参考、状态口径、自动事实与人工结论；按需复制 [报告模板](./assets/test-report-template.md)。
- [状态机示例](./examples/state-machine/test_session.c)：实际模块与测试分开编译，检查超时边界与 uint32_t 回绕。
- [双端协议示例](./examples/paired-protocol/test_link.c)：独立已知帧、丢包、旧轮次、重复保存与单端保存不等于双端成功。

每个用例写明前提、动作和可观察预期，检查状态、输出与不应发生的副作用。修复可复现缺陷时，尽量验证旧代码失败、修复后通过；不只检查文字、常量存在或内部函数调用次数。

## 执行和证据

- 先建立基线，再做最小修改；相关回归与要求的原工具链检查通过后，不无理由反复全量运行。
- 测试之间重置模块状态、虚拟时钟、模拟存储和通信队列；需要跨重启持久化的用例显式保留指定存储。
- 随机测试记录种子、事件序列和失败状态；回放同一输入应能重现失败。CPU 执行速度不能当作 MCU 实时性证据。
- 保存本次完整命令、编译器、源码哈希、结果与模型范围。编译失败、超时、测试失败均返回非零状态，不能读取历史日志冒充本次结果。
- 使用项目忽略的构建目录或系统临时目录，避免覆盖 IDE 产物；测试程序不烧录，不写真实设备存储。固件编译产物和本地工具路径不加入通用技能。
- 检查中断与主循环的共享状态、原子性和所有权；主机线程／顺序模拟不自动覆盖 MCU 抢占。检查数组、整数提升、对齐、DMA 缓冲区生命周期及 Cache 一致性；硬件替身不能证明这些目标条件已满足。错误路径必须有超时、取消和必要清理。

## 验证本技能的示例

在具备 Python 3 和主机 C 编译器的电脑上运行：

```text
python scripts/run_examples.py --cc /absolute/path/to/compiler
python scripts/run_examples.py --cc /absolute/path/to/compiler --negative-checks
```

从本技能目录运行，或使用脚本绝对路径；脚本按自身位置查找示例。支持常见 GCC／Clang／TinyCC 命令形式，不包含 MSVC 参数适配。日志、源码哈希、命令、summary.json 和自动执行摘要 report.md 写入新建的系统临时目录。负向检查只修改临时副本，用故意引入的错误验证测试能失败。

示例中的协议与超时参数是教学夹具，不是项目需求或芯片规范。不能把示例通过写成当前产品验证通过。

## 交付

按“修改／测试对象、覆盖与故障模型、命令与结果、证据位置、目标构建结果、实板未验证项”说明结论。断言数不是设备数、场景数、无线成功率或固定验收门槛。主机逻辑、原工具链构建、目标仿真与实板证据分别报告。

日常迭代可只保留机器记录；功能完成、版本交付或用户要求时生成适度的可阅读报告。自动摘要不推断需求全覆盖、无遗留缺陷或发布许可，正式报告的需求对应、限制和验收建议由人工确认。

与六阶段流程配合时，由流程的 Plan 阶段确定是否需要及覆盖范围，Verify 阶段检查证据；本技能提供测试方法，不额外增加与任务无关的审批或发布动作。
