# 从项目 AGENTS.md 提炼 Skill

用于“把当前 AGENTS.md 整理到技能库”等任务。默认先提炼可复用部分；除非任务明确包含源文件精简，不删除或替换项目 AGENTS.md。

## 内容去向

| 内容 | 去向 |
| --- | --- |
| 跨项目风险判断、实现约束、验证与交付方法 | 优先补充职责匹配的已有 Skill |
| 只在特定场景需要的长清单 | 对应 Skill 的 references，并从入口说明何时读取 |
| 芯片型号、编译器/Target、真实目录、引脚/DMA/NVIC、时钟、存储布局、测试命令 | 保留项目 AGENTS.md 或现有唯一权威文档 |
| 当前缺陷、待确认需求、板测未验收、设备擦写授权边界 | 保留项目事实源，不能泛化成其他设备已实现/已授权 |
| 用户语言、最小改动和提交偏好 | 按原有作用域保留；不借技能迁移扩大为无关任务要求 |

## 整理方式

- 阅读源文件及目标技能库规则、索引、已有 Skill 和 Git 状态，保护两边已有修改；核对真实编码，中文显示异常时先显式按 UTF-8 读取。
- 先按职责去重，不为每个项目复制整份 AGENTS.md；只有确有独立触发场景时才新建 Skill。项目专用技能标明 project 范围，不能用其快照替代实时源码调查。
- 把不变量、依据不足的停止条件、错误恢复和验收证据保留下来；六阶段材料可按风险缩减，不以固定流程数量代替正确性。
- 将具体数字改为“核对目标项目配置”，不能把某板卡的 IRQ 优先级、看门狗时间或 Flash 地址推广为通用默认值。
- 记录提炼来源及版本日期供追溯，不把原文件全文复制成第二份事实源；现有已确认目标与实现偏差分别表达。
- 仅提炼规则时不必执行固件构建或上板操作；现有命令若未执行，标为来源中的入口，不能宣称已验证其可用性。真正改变验证入口时再执行适用检查。
- 新增/更新引用和分类索引，验证 Frontmatter、相对链接、UTF-8、Diff 范围。只有发现具体可复用自动化需求时才增加脚本。
- 库要求同步挂载时先检查脚本行为和现有目标；已有正确 Junction 无需重建，实体目录或错误链接不得盲目递归删除。遇冲突只处理已确认范围。
- 汇报具体落点、源 AGENTS.md 是否变化、实际验证和同步状态；未经要求不提交、不推送。
