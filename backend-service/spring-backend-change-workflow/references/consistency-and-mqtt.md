# 一致性、并发与 MQTT 设备通信

仅阅读与当前变更相关的小节。先核实真实调用与协议，不将以下检查项当作目标项目已经实现的能力。

## 数据库与 Redis

- 确认事务实际生效的调用边界，包括代理调用、自调用、异常回滚条件、异步线程与不同数据源。注解存在不等于所有副作用处于同一事务。
- 同样检查 `@Async`、缓存注解等是否经实际代理触发，以及项目是否使用其他织入方式；不要从注解直接推断运行语义。核对缓存失效和消息发布发生在提交前还是提交后，再选择验证观察点。
- 余额、充值、使用次数等复合更新审查并发条件、约束和原子更新；幂等键应来自业务定义，明确作用域、有效期和重复请求的返回语义。
- 数据库写入、Redis 操作和消息发布通常不能由一个本地数据库事务共同回滚。先识别崩溃窗口及补偿/重试责任，再按现有架构选择最小修复；不默认引入分布式事务或 Outbox。
- 缓存失效、事务提交和并发读取之间可能出现旧值回填。分布式锁需核实获取失败、租约、所有者及释放路径；锁不代替数据库一致性约束。
- 金额/次数的单位、精度、上下限及溢出由业务定义。禁止借修复逻辑之机更改单位、清零历史值或重算真实数据。

## 异步任务与共享状态

- 识别状态的读写线程、可见性和原子性；线程安全集合或 `volatile` 不保证多步业务操作原子。
- 明确线程池/定时器的所有者、容量、拒绝策略、异常出口、超时取消和关闭路径；避免回调阻塞导致消息或请求积压。
- 任务重入、超时后的迟到结果及进程重启分别建模。超时不等于对端取消；重试前判断副作用是否已发生。
- 本地线程中的登录身份、数据范围和事务上下文不会自动随异步操作正确传播；核实显式传递与清理，避免跨用户串用。

## MQTT 与设备指令

- 同时核对发布端、订阅端、解析入口和正式协议；查清二进制/文本形式、长度、字节序、校验、命令字、Topic 和版本兼容。不猜测缺失字段，不擅自改变 CRC、QoS、重试或超时。
- 输入覆盖空载荷、短帧、非法长度、越界、无符号转换、未知命令和异常编码；解析完成前不写入业务状态。
- 区分应用接收请求、客户端提交发布、Broker 确认、设备业务 ACK 和实际执行完成。MQTT 的传输 QoS 不能单独保证业务副作用只发生一次。
- 明确序列号/业务 ID 与设备的关联规则、重复应答处理、迟到应答、断线重连、旧消息/保留消息及超时重发语义；不要因单次回调成功就关闭命令状态。
- 充值、锁定、清零等指令需验证幂等与授权；心跳/离线任务检查迟到心跳与超时任务的竞态，不擅自调整产品离线阈值。
- 联调前确认测试设备、环境及可接受副作用；优先使用纯解析测试或隔离 Broker。没有真实设备执行证据时明确标为未验证。

## 迁移与恢复

确认旧版本读写兼容、历史数据约束、迁移锁与耗时、失败中断和恢复方式。回退应用代码不一定能恢复被迁移或删除的数据；破坏性操作执行前需要已授权范围和可操作的备份/恢复安排。

## 可选验收场景

按变更选择，不要求每次全跑：同一业务请求并发/重复到达；数据库已提交但发布失败；设备已执行但 ACK 丢失；超时后收到旧 ACK；重启后任务恢复；无权限用户按设备 ID 发指令；非法帧到达时不产生持久化副作用。
