# 使用记录删除与清零验收

## 当前业务与协议依据

实施时先核对：

- 前端 `src/api/iot/deviceUsage/query.ts`、`index.ts`、`src/views/iot/deviceUsage/index.vue`。
- 后端 `IotDeviceUsageDeleteService`、`IotDeviceUsageServiceImpl`、`IotDeviceMqttServiceImpl`、`IotUsageResetAwaiter`、`IotDeviceMqttController`。
- `IotMqttFrameBuilder`、`IotMqttFrameValidator`、`IotMqttFrameParser`：模拟器复用构帧、校验和解析类；状态数据对应当前字段，不是独立的正式协议依据。
- 前端 `push.ts`、`push-message.ts`，后端 `PushHelper`、`MessageTopicListener`。

当前规则：指定单台设备，未设置开始时间、创建时间或序列号筛选时，新页面自动传 `resetUsed=true`，确认框说明清零。后端先检查权限、删除事务提交，再发送 `0x84`，HTTP 不等设备 ACK。无记录不删除、不清零。部分或单条删除不联动。接收匹配清零应答后提示“清零成功”；次数继续由状态上报更新。失败后可到设备页面手动清零，不自动重发。

连接与主题：

```text
仅本地测试 Broker
device/<获准设备编码>/ack  后端下发；模拟器仅订阅这一条主题
device/<获准设备编码>/up   模拟器上报；不发布通配主题
```

帧：`5A A5 | SEQ(4，大端) | LEN | CMD | DATA | 累加校验(1)`，设备编码 13 字节 ASCII。

- `0x80`：模拟连接上报，状态、已用及剩余次数；会更新本地设备状态。
- `0x84`：模拟器在 Success 模式返回同流水号 ACK 并将模拟已用次数设为 0；Timeout 模式既不执行清零也不回 ACK。
- `0x85`：返回与请求同流水号的当前模拟状态/次数。
- `0x88`：每 30 秒上报模拟心跳，保持本地在线。

模拟器忽略其他设备与其他命令，不实现充值、锁机或参数设置。客户端 ID 与后端不同，防止顶掉连接。真实设备仍在线上时无需修改其地址；本地和线上可以存在相同设备编码，测试结论必须明确环境。

## 顺序与断言

| 场景          | 操作                                     | 核验                                                                                                |
| ------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 部分删除      | 单条删除，或保留日期筛选执行删除所有     | 记录减少；不新增本轮 `0x84`；次数不因删除归零                                                       |
| 单设备全删    | 清除两个日期范围，只填获准设备编码       | 确认框说明清零；有效记录为 0；本轮只发一次 `0x84`                                                   |
| 成功应答      | 模拟器 Success                           | 指令/模拟器日志匹配同流水号；后台发布成功事件；状态上报后已用为 0，剩余次数不变；浏览器提示自动消失 |
| 超时          | 先 SetMode Timeout，准备少量记录，再全删 | 删除成功、命令已发送；等待当前配置的超时时间后提醒；无 ACK、无自动重发、模拟次数不被清零            |
| 无记录        | 全删后再次删除                           | 提示无记录；不新增清零命令                                                                          |
| 取消/重复点击 | 取消确认或连续点击                       | 取消无请求；提交期间互斥，结束后恢复                                                                |

已删空时不能直接重测删除联动；需要用户授权准备新记录。新建记录用工具返回的精确 ID 识别；不回填旧记录、不对其他设备操作。Seed 不修改设备信息表中的次数。

Review 使用 `-Since` 限定本轮时间，避免把旧 ACK 当成新结果。命令码在表中通常以十进制字符串保存：`132` 为 `0x84`，`133` 为 `0x85`。查询逻辑删除数据时分别报告有效数和删除标志，不将逻辑删除当物理清除。

## 证据与限制

日志只提取获准设备的命令/应答、成功/超时通知及明确异常，不输出 Token、密码、全部消息载荷或其他设备数据。日志正文中的日期筛选值不是日志时间，提取时间时锚定真正的日志行首，避免把 `00:00:00` 当操作时间。

2026-11-05 本次已验证：部分日期删除为 `resetUsed=false`，完整删除为 `true`；模拟器回清零 ACK，命令 `ACKED`，本地有效记录 0、已用 0、剩余 530；后台发布并消费成功通知。浏览器弹窗未直接观察，超时模式当时只实现、未做完整页面验收。既有单测 21/34 是该次结果，不是下一次的预期固定数量。

本次选择保留的两个问题：发送日志非 `ServiceException` 异常可能干扰发布结果；结果通知同步等待 Redis 可能延后 MQTT 回调。它们不是所有项目的已知故障；重新遇到再看当前代码，不在测试技能里自动修复或扩展架构。
