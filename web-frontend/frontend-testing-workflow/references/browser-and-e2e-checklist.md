# 浏览器与链路验收清单

单元测试与静态检查只能证明代码语法、类型与抽离逻辑正确，不能证明浏览器渲染、路由权限、Vite 代理转发、后端接口及硬件设备链路正常。涉及页面交互或联调时，按本清单执行核验。

## 1. 标准列表与 CRUD 交互自检

在浏览器中打开目标路由，逐项验证：

- **首屏与搜索**：进入页面自动触发一次列表加载，`loading` 遮罩正常显示与消失；输入筛选条件回车或点击“搜索”时，`pageNum` 重置为 `1`。
- **重置闭环**：点击“重置”后，普通输入框、下拉框、日期范围选择器均被清空，并重新拉取第一页数据。
- **分页与跨页状态**：切换每页条数（`pageSize`）或页码（`pageNum`）时携带当前生效筛选条件；删除当前页最后一条记录或执行条件删除后，列表与 `total` 同步刷新。
- **弹窗与表单生命周期**：
  - 打开“新增”弹窗时，表单字段与校验红字已重置，不残留上一次“编辑”的数据；
  - 打开“修改”弹窗时，先重置再拉取详情回填；
  - 提交期间按钮处于 `:loading` / `:disabled` 互斥状态，接口报错时恢复可点击且不关闭弹窗。
- **导出与下载**：点击“导出”调用公共下载封装，下载文件名符合业务约定；若后端返回权限错误或业务异常 JSON，应弹出错误提示而非下载损坏的文件。

## 2. 权限、安全与设备控制核验

- **权限指令与动态判断**：
  - 核对按钮权限指令（如 `v-hasPermi`）与后端接口权限标识一致；
  - 涉及组合权限（如删除记录同时需要设备控制权限才发送清零命令）时，分别验证有权限与无权限账号下的确认弹窗文案及请求参数。
- **大整数与字符串编号精度**：检查 Network 面板中的请求 URL 与响应 JSON，确认长整型 ID 未因 `Number` 转换丢失尾数精度，设备编码等字符串保留完整格式与前导零。
- **设备控制诚实反馈**：
  - 确认充值、锁定、解锁、清零、参数设置等操作均有二次确认与防重提交保护；
  - 区分“HTTP 请求成功 / 命令已下发”与“设备实际执行完成”，UI 文案与警告级别（`success` vs `warning`）须与后端返回的真实状态码对应。

## 3. 代理与网络异常排障路径（502 / 401 / 403 / 空白页）

浏览器联调遇到异常时，按以下顺序定位，不盲目修改公共配置：

1. **浏览器 Network 面板**：核对请求完整 URL、HTTP Method、Query String（是否包含未清洗的 `undefined` 或空串）、Request Payload 与 HTTP 状态码。
2. **前端 API 与请求层**：对照 `src/api/` 与请求封装（如 `src/utils/request.ts`），区分是 HTTP 状态码错误还是业务码（`code !== 200`）拦截。
3. **Vite 开发代理**：若出现 `502 Bad Gateway` 或 `ECONNREFUSED`，检查环境配置（如 `.env.development`）中的 API 前缀与 `vite.config.ts` 中 `server.proxy` 的 `target` 端口，确认对应后端服务是否已启动监听。
4. **控制台与路由守卫**：若页面空白，检查 Console 是否有未捕获的组件渲染异常、未注册组件或动态路由权限缺失。

## 4. 验证证据交付矩阵

在最终交付报告中，明确列出每一层的执行状态，不混淆层级：

| 验证维度 | 报告内容要求 |
| :--- | :--- |
| **Vitest 单元测试** | 执行命令、测试文件路径、通过的用例数（如 `17 passed`）及覆盖的核心分支 |
| **静态与类型检查** | 格式化检查、lint、Vue/TS 类型检查结果；如有历史基线报错需明确区分 |
| **生产构建验证** | 生产构建命令是否通过（涉及构建、公共层或导入变更时必报） |
| **浏览器与后端联调** | 实际验证的页面路由、交互步骤与观察结果；若因后端未启动或无测试设备未验证，明确列为**待验项** |
