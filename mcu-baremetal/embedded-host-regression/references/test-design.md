# 测试设计与故障模型

## 用例的独立依据

先从需求或协议写出“前提 → 输入／事件 → 预期状态和输出”，再选择断言。预期值不能调用待测算法算出来；编解码双方一致也可能共同偏离规范，需有独立已知帧向量。

| 对象 | 值得覆盖的行为 | 常见误区 |
| --- | --- | --- |
| 按键 | 两种组合顺序、短触碰、持键、释放隔离、退出后再按 | 只给一次事件，不测试消抖与事件交接 |
| 状态机 | 每条许可转移、非法操作、重入、取消与完成相遇 | 只测正常路径或枚举值 |
| 定时 | 临界点前／恰好到期／到期后、回绕、服务延期 | 用电脑 sleep 或运行速度代表 MCU 时序 |
| 协议 | 长度、校验、地址边界、旧轮次、重复帧、丢包 | 永远立即可靠交付，忽略两端状态不同 |
| 存储 | 无记录、损坏、版本不兼容、写入部分完成后重启 | 模拟保存永不失败或自动修复记录 |
| 算法 | 独立参考值、极值、饱和、单位、整数提升 | 只做正向转换再逆变换 |

同时检查禁止的副作用，例如忙状态不能延迟排队保存、重复包不能重复写入、退出不能重新发送旧灯效。

## 虚拟时间

时间作为输入或由可替换接口提供，测试推进时间后主动调用模块服务。区分设备本地时钟、消息交付时间与模型调度顺序；明确同一时刻先服务哪一端。

- 对无符号差值超时检查，在约定的最大间隔内验证回绕；不能宣称跨任意多次计数器回绕仍可区分时间。
- 除固定 1 ms 步进，还按需求加入不规则服务间隔、一次跨多节拍、截止点与取消同时发生。
- 不因一次调用跨过多个节拍就替固件补发积压命令，除非需求明确允许；验证实际丢弃、补发或合并策略。
- 不依赖断言次数判断真实持续时间，也不把虚拟服务负载作为目标最坏执行时间。

## 双端通信

连接真实发送端组帧和真实接收端解析，中间只放置可控制的传输队列。保留每帧内容、目标／来源、时间和丢弃原因，能够复现部分设备收到、漏收通知、重复副本、延迟旧包及断开后恢复。

区分“发送尝试”“模块状态”“接收端收到”“接收端执行业务”。没有回执的协议，不能由模拟器暗中保证送达或确认保存。先丢切换通知再发保存，和丢保存本身，是不同场景。

帧格式检查使用独立向量；状态检查覆盖双方默认值与当前值可能不同。不要让模拟器自动跟随发送端跳频，接收端是否换信道应由其实际代码决定。

## 存储与重启

按目标器件建立最小有效模型：容量、擦除单元、编程粒度、允许的位变化、失败返回及持久化提交点。只有已进入模型的行为才可写入覆盖声明。

在各写入／擦除步骤中断后，清除 RAM、重新运行真实加载逻辑，显式保留模拟非易失数据。检查恢复到旧有效记录或新完整记录，不能恢复混合数据。若旧槽仍有效，不应预设非法新槽必然导致出厂默认值。

EEPROM 与 Flash 不能共用不符合器件语义的全成功数组模型。模拟断电不能代替真实掉电、电压斜率、忙状态和擦写持续时间验证。

## 让失败有诊断价值

- 基线失败先定位是原缺陷、环境错误还是模型不成立，避免为通过测试修改无关业务。
- 用例可独立运行；随机序列记录种子，并保留失败轨迹。缩短失败序列有助于判断最小触发条件。
- 缺陷回归最好在旧逻辑上出现同一失败，再验证修复；故意修改临时副本也能检验测试是否对关键行为敏感，但不等于证明测试完备。
- 不要求每个私有函数调用顺序都固定；只有顺序本身是协议或安全约束时才验证它。
- 覆盖率用于寻找未检查的分支；高覆盖率、很多断言和很多随机轮次都不能单独证明需求满足。
